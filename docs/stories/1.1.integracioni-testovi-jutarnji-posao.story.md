# Story 1.1: Integracioni testovi za jutarnji posao i snapshot orkestraciju

## Status

Done

## Story

**As a** administrator klona koji se oslanja na nocni `stats snapshot` i jutarnji `posao dnevni`,
**I want** da orkestracija tih poslova (redoslijed poziva, error handling po oglasu, file lock,
odluka o slanju poruke) bude pokrivena testom,
**so that** regresija u `src/cli/index.ts` bude uhvacena prije produkcije, ne od strane klijenta
koji jutarnju poruku ne dobije ili dobije pogresnu.

## Acceptance Criteria

1. `src/core/snapshoti.ts` (round-trip snapshota, atomic write, preskakanje pokvarenog JSON-a)
   ima test fajl.
2. `posao dnevni` orkestracija ima integracioni test koji potvrdjuje: (a) poruka se NE salje kad
   `dnevniVrijedanSlanja` vrati false, (b) pojedinacna greska na jednom oglasu ne obara cijeli
   posao, (c) `me`/`refresh-limits` se pozivaju prije prvog `refresh`, i kvota dnevnik se upisuje,
   (d) `--suho` ne zove `refresh` endpoint.
2. `stats snapshot` orkestracija ima test za file lock i za gresku usred petlje (`posaoFail` put,
   exit 1).
3. Testovi radi na macOS i Windowsu (bez shell komandi, bez hardkodiranih portova/separatora).
4. `npm run typecheck`, `npm run build`, `npm test` prolaze, postojeci testovi ostaju netaknuti.

## Dev Notes

- Racunski/odlucivacki sloj (`src/core/stats.ts`, `src/core/izvjestaj.ts`) je vec dobro testiran
  prije ove price — `dnevniVrijedanSlanja` (`izvjestaj.test.ts`) i `zauzmiKljuc`
  (`plan-fajl.test.ts`) NISU ponovo testirani, samo je CLI put koji ih koristi provjeren.
- `src/cli/index.ts` orkestrira sve kroz inline `.action()` closures, bez izvezenih funkcija —
  integracioni test ide kroz subprocess (`node dist/cli/index.js ...`), ne kroz import.
- Throttle (`OLX_MIN_REQUEST_INTERVAL_MS`) i retry (`OLX_MAX_RETRIES`) na 5xx bi test sa greskom
  ucinili sporim (~10s) — testovi postavljaju oba na 0 preko postojecih, dokumentovanih env
  parametara, ne kroz test-only flag u produkcijskom kodu.
- Zateceno ponasanje, dokumentovano u testu, ne "popravljeno": `zapisiKvotu` u `posao dnevni`
  se poziva i pod `--suho` (linija je iznad grane `if (!opts.suho)`).
- Scenariji sa obnovama zahtijevaju upisan `.olx-pik/ritam-obnova.json` — bez zapisane odluke
  klijenta posao samo pita (`obnove_stanje: "ceka_odluku"`) i ne obnavlja nista.
